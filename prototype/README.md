# 川辺の制作街・街区レビュー

[街を開く](review/walk.html) ／ [橋の眺めの2案を理想画像と比べる](review/vista.html) ／ [俯瞰と石橋からの変更前後を見る](review/compare.html)

初回は石橋で「歩く」から始まる。左手のPISOLA、右手のSISTER、その奥の坂の上にゲーム展示館がある。「街を眺める」を選ぶと、同じ街区を川の上から見渡せる。歩行中の地点・向き・画角は、俯瞰から「歩く」に戻ると復帰する。

| モード | PC | タッチ |
| --- | --- | --- |
| 歩く | WASD・矢印で前後左右に歩く。ドラッグで見回し、Q/Eで左右を向く | 方向ボタンを押し続けて歩く。1本指で見回す |
| 街を眺める | ドラッグまたはQ/Eで回転。ホイール・＋/－でズーム。右ドラッグ・Shift＋ドラッグ・WASD・矢印で移動 | 1本指で回転。2本指をそろえて移動。ピンチでズーム |
| 橋の眺め | ドラッグまたはQ/Eで少し見回す。案A・案Bで構図を切り替え、もう一度押すと元の構図に戻る | 1本指で少し見回す。案A・案Bをタップして切り替え |

歩行中は「視点を移す」で石橋・各店先・丘の前庭へ移れる。入口に近づくと現在地に入口名が表示される。

## 景観と撮影条件

石橋を渡るとSISTERとPISOLAの店先で石畳が広がる。橋を渡って左へ折れると幅1.85mの川沿いの小路があり、民家の玄関と小庭の間を抜けて坂道へ合流する。SISTERの裏手からも住宅の横丁を経て丘へ上がれる。各戸の玄関に向かう小径の幅は1.10m。民家57棟は路地に玄関を向け、間口・階高に合わせて切妻、寄棟、片流れ、屋上テラスやパーゴラを組み合わせた。

左岸の民家は住宅路地側に寄せて軒を下げた。川岸から高さ0.29m、0.58m、0.89mの順に石積みの花壇が続く。SISTERを少し奥へ移して正面を石橋へ向け、坂の内側にあった家を住宅地に移した。坂は中央で左に振れてから右に登り、標高8.10mの展示館前庭に着く。

今回の造形では、オリーブの樹冠とヤシの葉を小さな厚い角形で組み、葉の密度と空が抜ける隙間を変えた。花は紫・桃・黄の群れごとに背丈と間隔を変え、石垣から垂れる蔓を重ねている。近景の石積みには欠けた角、深い目地、石ごとの張り出しを付け、石畳も影を落とす立体にした。PISOLAの低い濃色屋根は細かな重ね葺き、SISTERの入口の小屋根は厚みのある角張った丸瓦で描いた。夕日を暖め、軒下と葉の根元の暗さを強めた。

3棟の形・外壁・開口は元の店舗画像に沿っている。理想画像の完全な再現には至っておらず、樹形、花の密度、背景住宅や細部の造形に差が残っている。

## 橋の眺め（鑑賞視点の2案）

[理想画像と2案を比べる](review/vista.html)。「橋の眺め」モードで、南東岸から石橋の東面越しに街を見る固定の鑑賞視点を選べる。`walk.html#vista-a`・`walk.html#vista-b` で直接開ける。どちらを残すかは未決定。

| 案 | 画面 | カメラ位置 | 注視点 | 縦画角 |
| --- | --- | --- | --- | --- |
| 案A 橋の脇 | 横長 | (9.0, 4.0, 27.8) | (-2.8, 0.9, -6) | 54° |
| 案A 橋の脇 | 縦長（縦横比0.8未満） | (9.2, 4.0, 28.2) | (-2.6, 0.2, -6) | 68° |
| 案B 東岸の高台 | 横長 | (6.8, 6.8, 31.5) | (-1.8, 1.0, -7) | 47° |
| 案B 東岸の高台 | 縦長 | (6.8, 8.6, 37) | (-2.2, 1.2, -8) | 66° |

案Aは3連アーチと水面が手前に入り、オリーブの葉が左上を縁取る。展示館はSISTERの陰になり、棟番号と高窓の一部だけが見える。案Bは曲がる坂と展示館の正面全体が見えるが、見下ろすためアーチはほとんど見えない。見回しは左右±0.32、上下±0.18ラジアン（約18°・10°）まで。歩行位置と俯瞰の状態は鑑賞視点に入っても変わらず、戻ると元の場所から再開する。

石橋の側面は段状の箱で、横から見てもアーチに読めなかった。これを3連の楕円アーチに置き換えた。各アーチは径間4.16mで、迫石19個（中央は要石）、暗めの穹窿の裏面、川中の橋脚2基の水切りで構成する。歩行の通路と通行判定は変えていない。街全体の配置がずれないよう、元の橋の色の抽選回数は残している。

夕日と反対側を向く面に、川と石畳から返る弱い暖色光（影なし）を足した。PISOLAの軒下にはペンダント照明の光が店先へこぼれる点光源を置いた。オリーブとヤシの葉は、太陽を背にした面が薄く透け、太陽の方向を見ると黄緑に光る。1280×800の同一カメラで画面領域の輝度を測ると、輝度60未満の画素の割合は次のとおり。

| 領域 | 変更前 7a57916 | 変更後 |
| --- | --- | --- |
| 案Aの左上の葉 | 63.2% | 18.7% |
| 案AのPISOLA正面 | 53.3% | 27.0% |
| 案Bの左の葉 | 66.6% | 18.1% |
| 案BのPISOLA正面 | 55.7% | 28.0% |

返り光は全体に効くため、SISTERの側面など日陰の面もやや明るくなり、陰影は前回より浅い。

## 動作確認

Windows版Chrome（Intel Iris Xe・D3D11）で単独HTMLを開いた。1280×800ではキーボード、375×812では方向ボタンの模擬タッチで石橋 → SISTER → PISOLA → ゲーム展示館を連続して歩き、3か所で入口名を確認した。

両サイズで、石橋から川沿いの路地を曲がり、民家の玄関の石段まで歩いた。これとは別に、歩行と同じ通行判定で16cm間隔の格子を石橋から探索し、57戸すべての玄関前へつながることを確認した。俯瞰の回転・移動・ズーム後には歩行位置、向き、画角が復帰した。

歩行中と俯瞰回転中に各90フレームを、他のブラウザー検証と同時実行せずに測定した。全条件でフレーム間隔の中央値は16.7msだった。95パーセンタイルは次のとおり。

| 撮影サイズ | 歩行 | 俯瞰回転 |
| --- | --- | --- |
| 1280×800 | 16.8ms | 16.9ms |
| 375×812 | 16.9ms | 16.8ms |

石橋の初期位置で描画される三角形数は、PCで約94万から201万、375px幅で約86万から192万へ増えた。俯瞰の初期位置ではPCが約98万から210万、375px幅が約91万から201万。遠景の花は花穂を少ない立体で表し、石の欠けは店舗付近と橋に限っている。影は静止した街の初回描画時に計算し、PCは4096px、375px幅は2048pxのシャドウマップを使う。

スマホ幅の確認はPC上のタッチエミュレーション。スマートフォン実機とSafariの描画速度は未計測。

### 橋の眺めの確認（2026-11-25）

ヘッドレスChrome 157（Intel Iris Xe・D3D11）でChrome DevTools Protocolから実入力を送った。1280×800ではキーボードとマウス、375×812では模擬タッチで、次の順に操作した。石橋から歩いて見回す → 橋の眺め（案A）→ 案B → 見回し → 案Bを再選択して構図に戻す → 歩く → 街を眺めて回転 → 橋の眺め → 街を眺める → 歩く。両サイズで、歩行に戻るたびに鑑賞前と同じ位置・向き・画角になり、俯瞰の回転状態も保たれた。鑑賞中のWキーで歩行位置は動かなかった。案のボタンは、ドラッグ直後のタップでも切り替わる。

描画負荷は、変更前（7a57916）と変更後を同じ手順で測った。各条件で毎回再読み込みし、20フレーム描いてから180フレームの間隔を測る。歩行の開始位置・案A・案Bの3視点を2サイズで2回ずつ測った。全条件で中央値は16.7ms。20msを超えたフレームは次のとおり。

| 撮影サイズ | 変更前 | 変更後 |
| --- | --- | --- |
| 1280×800 | 76 / 1080 | 136 / 1080 |
| 375×812 | 0 / 1080 | 29 / 1080（歩行の1回のみ） |

1280×800は回ごとの揺れが大きく、同じ条件でも0〜64フレームの幅がある。PISOLAの点光源を外した変更後でも111 / 1080だった。描画される三角形数はほぼ同じで、PCの石橋で約199.1万から198.8万、案Aの位置で約196.2万から195.9万。今回はヘッドレスでの計測で、前回のブラウザー表示での値とは直接比べられない。

#### 窓ありのChromeでの再確認（レビュー担当）

窓ありのWindows版Chrome 157（Intel Iris Xe・D3D11）で、Chrome DevTools Protocolから実際のキー・マウス・タッチ入力を送った。この端末の画面は論理1280×752（表示倍率150%）で、1280×800の表示領域を窓では取れない。そのため、1280×800は表示領域の寸法指定（DPR 1.5）、375×812はタッチの模擬（DPR 3）で開いた。窓は画面外に置き、背面でも描画を止めない設定にした。同じ流れを3回通し、すべて同じ結果になった。

| 確認項目 | 結果 |
| --- | --- |
| 1280×800　歩行 → 案A → 案B → 見回し → 案Bを再選択 → 歩く | 合格。案A・案Bとも位置と画角は記録どおり。ドラッグでもQ/Eでも、見回しは左右±0.32・上下±0.18ラジアンで止まる。鑑賞中のWキーで歩行位置は動かない。案Bの再選択で見回しが0に戻る。歩行に戻ると位置・向き・画角が鑑賞前と一致する |
| 1280×800　歩く → 街を眺める（回転・ズーム）→ 橋の眺め → 街を眺める → 歩く | 合格。俯瞰の位置・向き・画角48°と、歩行位置の両方が保たれる。橋の眺めは前回選んだ案Bで再開する |
| 375×812の模擬タッチ　同じ流れをタップで | 合格。ドラッグ直後に案Bのボタンを1回タップすると切り替わる。方向ボタンは鑑賞中と俯瞰中に隠れ、歩行に戻ると現れる。1本指ドラッグの見回しも同じ範囲で止まる。ピンチ後の俯瞰も保たれる |
| URL直開き | 合格。`#vista-a`・`#vista-b` はその案の鑑賞視点で、`#overview` は俯瞰（画角48°）で開く。`#pisola` は (-4.3, -2.5)・向き0.95の歩行で開く。ハッシュなしは石橋の開始位置 |
| 縦横比の切り替え | 合格。1280×800 → 800×1000 → 799×1000 → 1000×800 → 375×812 → 812×375で、縦横比0.8ちょうどは横長用、0.8未満は縦長用の位置と画角に切り替わる。案Bでも同じ。表示領域の指定を外して窓を1280×752 → 520×752 → 900×600に変えたときも追従する |
| 石橋から3入口まで歩く | 合格。歩行と同じ通行判定の格子探索で経路を求め、実際のWキーとマウスの向き変えで歩いた。PISOLA・SISTER・ゲーム展示館の3入口で入口名が表示された。0.2m間隔の格子で通行可能な16,721点は変更前と完全に一致し、アーチの改修は通行判定に影響していない |
| コンソール | エラーなし。警告は読み込みごとに1件だけで、同梱のThree.js r160（`three.min.js`）が出す非推奨の告知。変更前から出ている |
| スマートフォン実機・iPhone Safari | 未確認。この環境では実機と端末エミュレーターに接続できない |

1280×800、DPR 1.5（描画バッファ1920×1200）でも描画負荷を測った。この端末の実際の表示倍率に当たる条件。各条件で再読み込み後に30フレーム描いてから、180フレームを2回ずつ測った。中央値は変更前の歩行1回（33.2ms）を除いて16.7ms。20msを超えたフレームは、3視点×2回（1080フレーム）の合計で次のとおり。

| 版 | 20ms超 |
| --- | --- |
| 変更前 7a57916 | 269 / 1080 |
| 変更後 | 217 / 1080 |
| 変更後から返り光と点光源を外した版 | 191 / 1080 |

この倍率ではどの版も1〜2割のフレームが落ち、条件と回による揺れ（7〜107）が追加光の差より大きい。追加した2つの光による悪化は、この計測からは確認できない。負荷の主因は表示倍率による描画画素数で、端末での滑らかさを上げるなら画素比の上限（現在1.6）を下げる案がある。

#### 見た目のレビュー所見

比較画面で理想画像と2案を見比べた。構図の数値は、ユーザーが案を選ぶまで変えない。

- **375px幅の案A**：PISOLAの左翼が画面の左端（左から5px）まで届き、左端の窓と軒先、左のヤシが枠外に出ている。下端では手前の花の穂先だけが切れて覗き、水面が画面の下3割強を占める。オリーブの葉は入らない。提案：注視点をやや左へずらすか、カメラを少し後ろへ下げてPISOLAの左に余白を作る。あわせて注視点を上げ、水面と花の切れ端を減らす。
- **375px幅の案B**：高い位置から見下ろすためアーチは見えない。建物も山もない空だけの行は画面の上23.6%で、見出しと案のボタンがその上に重なる（案Aは26.0%）。提案：アーチを見せるには、カメラを下げて橋に寄せる必要があり、その場合は案Aに近づく。案Bを選ぶ場合は、空を減らすより坂と展示館の見え方を優先するほうが、この案の役割に合う。
- **返り光による陰影**：案AのSISTER側面（日陰）の平均輝度は33.8から50.4に上がり、日向の正面（79.1から85.8）との比は2.34から1.70に縮んだ。日陰が赤寄りにもなり（赤／青の比2.3から3.2）、設計の「青紫寄りの日陰」から離れている。提案：返り光を0.62から0.3前後に弱め、色を中立から青寄りにする。PISOLA正面の明るさは点光源と窓の光で補う。どちらも案の選択後に、同じカメラで暗部の割合を測り直して決める。
- **理想画像との差**（2案共通）：店先の花の量と近景の大きな花群、PISOLAの装飾板の色の強さ、灯りの暖かさ、手前を流れる小川の近さに差が残る。案Aは「手前に川とアーチ・左上に葉」の骨格が理想画像に最も近い。

`index.html` が通常の入口。`python prototype/review/build_walk.py` で同じソースから単独HTMLを再生成できる。Three.js r160（0.160.1、MIT）を同梱しており、ローカルでWebGLが使えるブラウザーから開ける。
